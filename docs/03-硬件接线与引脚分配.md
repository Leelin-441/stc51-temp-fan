# 硬件接线与引脚分配

> 本文档是接线的**唯一依据**。所有引脚定义都可以在
> [`firmware/config.h`](../firmware/config.h) 里找到对应宏，两者必须一致；
> 改了一边就要同步改另一边。

---

## 0. 接线总原则（背下来能省一整天的排查时间）

1. **电机绝对不能直接接 51 的 IO 口。** IO 口只能输出约 20mA，电机启动要几百 mA，
   直接接会烧掉单片机。必须经过 ULN2003 或三极管驱动。
2. **所有 GND 必须连在一起（共地）。** 不共地会出现：电机乱转、串口乱码、DS18B20 读不到。
3. **电机用独立 5V 供电**，并在电源两端并一个 470µF 电解电容。
4. **DS18B20 的 DQ 必须有 4.7kΩ 上拉到 +5V**，否则永远读不到数据。
5. **电机两端必须反并联一只 1N4007 续流二极管**，否则关断瞬间的反向电动势会击穿驱动管。
6. 接线完成、**通电之前**，先用万用表蜂鸣档量一遍 +5V 与 GND 是否短路。

## 2. 逐模块接线表

### 2.1 DS18B20 温度传感器（本项目唯一的"外接传感器"）

| DS18B20 引脚 | 接到 | 说明 |
|---|---|---|
| VDD（1 脚） | 开发板 **+5V** | |
| DQ（2 脚） | 开发板 **P3.7**（板上 18B20 座的数据脚） | 单总线数据 |
| GND（3 脚） | 开发板 **GND** | |

**要点**

- **必须有一个 4.7kΩ 电阻把 DQ 拉到 +5V。**
  普中/清翔开发板在 18B20 座附近一般已经焊好了一个上拉电阻，
  但并不是所有版本都有。**怎么确认**：断电后用万用表电阻档量 18B20 座的
  DQ 脚与 VCC 脚之间，读数在 4.7kΩ 左右就说明已有上拉，不用再加；
  读数是无穷大就必须自己接一个。
- 如果用面包板外接 DS18B20，接线是：
  `DS18B20 VDD → +5V`，`DQ → P3.7`，`GND → GND`，
  再在 `DQ` 与 `+5V` 之间跨接 **4.7kΩ**。
- 杜邦线尽量短（≤20cm）。线太长会让 1-Wire 的上升沿变缓，时序出错。
- **两次读取之间必须间隔 ≥1 秒**（12 位转换需要 750ms）。本工程用 1 秒。

### 2.2 按键 K3 / K4

板载独立按键，**不需要额外接线**，只需确认跳线帽位置（有些板子用跳线选择
"独立按键"还是"矩阵键盘"）。

| 按键 | 引脚 | 说明 |
|---|---|---|
| K3（SET 键） | **P3.2** | 切换 自动/手动；长按恢复默认 |
| K4（UP 键） | **P3.3** | 调目标温度 / 手动切档 |

**要点**

- K1(P3.1) 和 K2(P3.0) 是串口的 RXD/TXD，**本项目故意不用它们**，
  这样按键和串口可以同时工作，测试时不用拔线。
- 按键低电平有效（按下为低）。板上有上拉电阻；如果是自制按键模块，
  记得在引脚与 +5V 之间加 10kΩ 上拉，或把引脚配置成内部上拉（本项目代码用板上拉，
  自制按键需要外接 10kΩ 到 +5V）。

### 2.3 LCD1602 字符液晶（主显示器）★ 直接插在板子的专用插座上

**本项目不需要为 LCD 接任何一根线** —— 普中 PZ-51 实验板上有 LCD1602 专用插座，
把液晶插上去就行。**插座是出厂焊死的固定接线**，所以驱动必须跟着板子走。

**普中 PZ-51 的 LCD 插座接线（固定，不可更改）**

| LCD1602 引脚 | 编号 | 板上接到 | 说明 |
|---|---|---|---|
| VSS | 1 | GND | |
| VDD | 2 | +5V | |
| V0 | 3 | 板上电位器 RJ1 中间脚 | 对比度，**见下方** |
| RS | 4 | **P2.6** | 0=命令，1=数据 |
| RW | 5 | **P2.5** | 代码固定拉低（只写不读） |
| E | 6 | **P2.7** | 使能，下降沿锁存 |
| D0~D7 | 7~14 | **P0.0 ~ P0.7** | 8 位模式；板上已为 P0 焊了上拉排阻 |
| A（背光+） | 15 | +5V | |
| K（背光−） | 16 | GND | |

> ⚠️ **这是本项目踩过的最大一个坑。**
> 早期版本按"自己接线"的思路，把 LCD 设计在 **P1 口的 6 个空闲脚**上，
> 还写进了文档。结果插到普中的专用插座上**完全对不上**，
> 现象就是**屏幕上只有一排黑方块**（液晶停在上电默认状态，收不到任何有效命令）。
> 排查了两轮才从实物照片上发现：**这块板的 LCD 是插座直连的，不是杜邦线接的。**
> 教训：**用开发板时，先确认板子的外设是怎么连的，再决定代码怎么写。**

**对比度 V0**

普中板上已经焊好了对比度电位器（丝印 **RJ1**，在 LCD 插座附近），
**上电后直接旋它**：转十几圈才到位置，不要以为转一下没变化就是坏了。

| 现象 | 原因 |
|---|---|
| 屏幕空白（只有背光） | 对比度太低，继续朝一个方向旋 |
| 满屏深色、看不清字 | 对比度太高，反方向旋 |
| **一排整齐的黑方块** | **不是对比度问题** —— 是液晶没收到初始化命令（见上方 ⚠️） |

**要点**

- **P0 是整口写的**（`LCD_DATA_PORT = dat;` —— `P0 = 数据`），因为 LCD 独占这 8 根线。
  代价是板载数码管会跟着乱显示，拔掉它的电源跳线帽即可。
- **P2.5 / P2.6 / P2.7 用 `sbit` 逐位写**，不会碰到 P2.0/P2.1 的 LED、
  也不会碰到 P2.2~P2.4 的数码管位选。
- **D0~D7 的顺序不能接错**（板子已经接好了，所以这条只在你换板子时才需要考虑）。

**关于板载数码管（本项目不用）**

普中板上 P0 **同时**接到数码管的 74HC245 段选，所以**写 LCD 的时候数码管会跟着乱显示**。
这是正常的，两种办法处理：

1. **拔掉数码管模块的电源跳线帽**（板上一般标着 `J24` 或类似丝印）—— 推荐，一劳永逸
2. 不管它 —— 只是难看，不影响 LCD 和整个系统

> 想改回用数码管显示的话，把 `firmware/legacy-smg/` 下的 `smg.c` / `smg.h`
> 加回工程、把显示函数换回去即可。但注意 P0 是共用的，**LCD 和数码管不能同时用**。

### 2.4 双色 LED（板载）

| LED | 引脚 | 说明 |
|---|---|---|
| 绿 | **P2.0** | 低电平点亮，表示电机在运行 |
| 红 | **P2.1** | 低电平点亮，报警/故障时闪烁 |

**要点**

- 特意只用 P2.0/P2.1，因为 P2.2~P2.4 已经被 74HC138 拿去当数码管位选了，
  用这两个不会打架。

### 2.5 蜂鸣器（板载）

| 信号 | 引脚 | 说明 |
|---|---|---|
| BEEP | **P1.5** | 低电平响（板上三极管驱动） |

**要点**

- 有些版本的开发板把蜂鸣器接到了 **P2.5**，并且用跳线帽选择。
  如果自检时蜂鸣器不响，检查跳线，或者把 `config.h` 里的
  `sbit BEEP = P1 ^ 5;` 改成 `P2 ^ 5`。
- 如果板载蜂鸣器是**无源**的（没有内部振荡电路），它需要 2~4kHz 方波才会响，
  本工程直接给电平不会出声。解决：改成有源蜂鸣器模块，或者用定时器输出方波驱动。
  区分方法：有源的背面通常封着黑胶，无源的能看到绿色电路板。

### 2.6 电机 + 驱动（本项目最需要小心的地方）

**完整电路图见下图：**

![电机驱动电路](images/fig4-motor-driver.png)

#### 方案 A：用板载 ULN2003（推荐，零成本）

普中/清翔开发板上那颗 16 脚的 ULN2003 就是步进电机驱动芯片，
它同样是驱动直流电机的理想器件。**确认方法**：找板上标着 `ULN2003` 的芯片，
以及标着"步进电机"的 4 针或 5 针接口。

| 连接 | 接到 |
|---|---|
| 51 的 **P1.0** | ULN2003 的 **IN1**（板上已经连好，一般在步进电机接口旁标注） |
| **+5V** | 电机 **正极** |
| ULN2003 的 **OUT1** | 电机 **负极** |
| ULN2003 的 **COM** | **+5V**（内部续流二极管的公共端） |
| ULN2003 的 **GND** | **GND**（必须与单片机共地） |

> ⚠ **ULN2003 是"低边开关"，而且是反相的。**
> 输出脚 OUT 平时是"悬空"的，导通时被拉到 GND。
> 所以**负载必须接在 +5V 与 OUT 之间**。
> 如果把电机接在 OUT 与 GND 之间，它**永远不会转**（这是最常见的接错）。

> ⚠ **板上 ULN2003 的 IN1~IN4 一般对应 P1 口的低 4 位**，
> 而这四个脚也常被"矩阵键盘""流水灯"模块共用，靠跳线帽切换。
> 接之前确认跳线帽拨到了"步进电机 / ULN2003"一侧。

#### 方案 B：自己搭 S8050 三极管（约 0.5 元）

如果板子上没有 ULN2003，或者你想用面包板搭：

| 元件 | 连接 |
|---|---|
| S8050 (NPN) | 发射极 E → GND，集电极 C → 电机负极 |
| 1kΩ 电阻 | 51 的 P1.0 → 1kΩ → 三极管基极 B |
| 10kΩ 电阻 | 基极 B → GND（下拉，防止单片机复位期间引脚悬空导致电机乱转） |
| 1N4007 二极管 | **反并联在电机两端**：负极接 +5V，正极接电机负极 |
| 电机 | 正极 → +5V，负极 → 三极管集电极 C |

#### 无论哪种方案，这两样都必须有

1. **470µF 电解电容**并在 5V 电源两端（注意正负极，接反会炸）。
   电机的启动电流是稳态的 3~5 倍，电容就是用来吸收这个冲击的。
2. **1N4007 续流二极管**反并联在电机两端。
   电机是感性负载，断电瞬间会产生反向电动势，没有它就会击穿驱动管。
   ULN2003 内部已经集成了续流二极管，用方案 A 时不必额外加。

#### 如果电机完全不转怎么办

按这个顺序排查：

1. 用 `SELFTEST_MODE` 自检程序，看串口是否打印 `duty = 100 %` —— 排除软件问题
2. 用万用表量 ULN2003 的 OUT1 对 GND 的电压：duty=100% 时应该接近 0V
3. 量电机两端电压：应该接近 5V
4. 如果 OUT1 是 0V 但电机不转 → 电机坏了，或者接成了"OUT 与 GND 之间"
5. 如果 OUT1 一直是 5V → IN1 没有收到信号，检查 P1.0 的跳线

### 2.7 串口（USB 转 TTL，用于自动化测试）

如果你的开发板上有板载 USB 下载电路（CH340），插上 USB 线就能用，
**不需要额外接线**。如果要用独立模块：

| USB-TTL 引脚 | 接到 | 说明 |
|---|---|---|
| TXD | 单片机 **P3.0**（RXD） | 收发**交叉**接 |
| RXD | 单片机 **P3.1**（TXD） | |
| GND | **GND** | |
| VCC / 5V | **不接！** | 板子自己供电，接上去可能电源打架 |

**要点**

- 串口参数：**9600，8 数据位，1 停止位，无校验，无流控**。
- ⚠ **不是 115200！** 51 在 11.0592MHz 下跑 9600 的误差是 0%，
  但 115200 的误差很大，一定乱码。
- **如果你的板子是 12MHz 晶振**：本工程代码会自动把波特率降到 **4800**
  （见 `firmware/uart.h` 里的 `#if (FOSC_HZ == 11059200UL)`），
  串口助手和测试脚本也要改成 4800。
- 最常见的错误是 TXD 接 TXD（应该交叉），症状是"完全收不到数据"。

## 3. 供电方案

```
   ┌────────────────────┐
   │  USB 5V 电源        │   充电宝 / 5V 2A 适配器（电机场景建议 ≥2A）
   └─────┬────────┬─────┘
         │        │
         │        ├──────────────► ULN2003 的 COM 脚
         │        │
         │        └────[470µF]────► 电机正极 ── 电机 ── ULN2003 OUT1
         │                    （电容并在电源两端）
         │
   ┌─────▼──────────────┐
   │ 51 开发板（USB 供电）│  板载 LDO 把 5V 转成 5V/3.3V 供各芯片
   └─────┬──────────────┘
         ├────────────► DS18B20 VDD
         └────────────► LCD1602 / LED / 蜂鸣器

   ★ 所有 GND（USB 电源、开发板、ULN2003、电机电源）必须连在一起
```

**两种可行方案**

| 方案 | 做法 | 适用 |
|---|---|---|
| A（推荐） | 一个 5V 2A 适配器给所有东西供电，开发板也从这个 5V 取电 | 桌面演示最省事 |
| B（最稳） | 开发板用 USB 线供电；电机的 5V 单独用一个电源或充电宝；两者 GND 相连 | 电机功率大、容易引起复位时 |

**绝对不要**：把电机接到开发板的 5V/3.3V 排针上直接取电。
电机的冲击电流会把板上的电压拉垮，单片机立刻复位。

## 4. 上电前自检清单

- [ ] 万用表蜂鸣档量 +5V 与 GND：**不导通**（不短路）
- [ ] 电机的 5V 电源与开发板的 GND：**导通**（已共地）
- [ ] 470µF 电解电容**正极接 5V、负极接 GND**（接反会炸）
- [ ] 1N4007 续流二极管方向正确：**负极接 +5V，正极接电机负极**
- [ ] DS18B20 的 DQ（P3.7）与 +5V 之间有 4.7kΩ（万用表量一下）
- [ ] 电机接在 **+5V 与 ULN2003 的 OUT1 之间**（不是 OUT 与 GND 之间）
- [ ] ULN2003 的 COM 接 +5V，GND 接 GND
- [ ] 板上 ULN2003 的跳线帽拨到了"步进电机 / ULN2003"一侧
- [ ] 蜂鸣器跳线帽位置正确（P1.5 还是 P2.5）
- [ ] 独立按键跳线帽拨到了"独立按键"一侧（不是矩阵键盘）
- [ ] 串口模块的 TXD→P3.0、RXD→P3.1（**交叉**），VCC 没接
- [ ] 杜邦线都插到底了，没有半插的

## 5. 常见接线错误 → 症状对照表

| 症状 | 最可能的原因 |
|---|---|
| **LCD1602 完全不亮（背光也不亮）** | A/K 没接 +5V/GND；或整块没供电 |
| **LCD1602 背光亮但屏幕空白** | **最常见：V0 对比度没调** → 接 10kΩ 电位器并旋转，或把 V0 接 GND 试试 |
| **LCD1602 满屏黑方块** | 对比度调得太高 → 反方向旋电位器；或 V0 直接接了 +5V |
| **LCD1602 显示乱码 / 字符不对** | 数据线虚接；或换过板子后 D0~D7 顺序不对 |
| **LCD1602 只显示一排黑方块** | **不是接线问题** —— 是液晶没收到有效命令，检查驱动引脚是否与板子插座一致 |
| **改显示的时候电机转速乱跳 / 蜂鸣器乱响** | 代码里出现了整口写 P1（本工程用 sbit 逐位写，已避免） |
| DS18B20 读不到（串口 SENSOR 一直是 NOPRESENT） | 缺 4.7kΩ 上拉；或 DQ 没接 P3.7；或 VDD/GND 接反 |
| DS18B20 读数一直是 85.0℃ | 上电默认值，说明转换没完成 → 检查读指令时序（本工程已处理） |
| DS18B20 读数一直是 0.0℃ | 假货传感器，或供电不足；换一个试试 |
| DS18B20 偶发 CRC 错误（BADCRC） | 杜邦线太长 / 受干扰；缩短线长，DQ 与 GND 之间加 100nF 电容 |
| **电机不转，但液晶显示 `P=100`** | 最常见：电机接在了 OUT 与 GND 之间（应接在 +5V 与 OUT 之间） |
| 电机不转，液晶显示 `P=  0` | 温度没到进档门限；按 K4 把目标温度调低试试 |
| 电机一启动单片机就复位 | 电机从开发板取电了；没共地；缺 470µF 电容 |
| 电机转速不变，只有"转/不转" | IN1 没接 P1.0，或接到别的脚了；核对跳线 |
| 电机低速档只有嗡嗡声不转 | 占空比太低转矩不足；把 `MOTOR_DUTY_LOW` 从 34 调到 40 |
| 电机一直全速转不停 | P1.0 被短路到 +5V；或 `MOTOR_ON` 极性反了 |
| 蜂鸣器不响 | 跳线帽在 P2.5 而代码用 P1.5；或蜂鸣器是无源的 |
| 蜂鸣器一直响 | `BEEP_ON` 极性搞反了（代码里改成 `GPIO_PIN_SET` 对应的 1） |
| 按键没反应 | 独立按键跳线帽在"矩阵键盘"一侧 |
| 串口完全收不到数据 | TXD 接了 TXD（应该交叉）；CH340 驱动没装 |
| 串口乱码 | 波特率不是 9600；或板子是 12MHz 晶振，要改用 4800 |
| 下载时提示"握手失败" | 需要冷启动：先点下载，再给板子断电重上电 |

## 6. 引脚分配总表（与代码对照）

| 引脚 | 功能 | 方向 | 上电默认 | `config.h` 里的宏 |
|---|---|---|---|---|
| **P0.0 ~ P0.7** | **LCD1602 数据 D0~D7**（整口写） | 输出 | 由 LCD 驱动控制 | `LCD_DATA_PORT` |
| **P2.5** | **LCD1602 RW** | 输出 | 0（写模式） | `LCD_RW` |
| **P2.6** | **LCD1602 RS** | 输出 | 0（命令） | `LCD_RS` |
| **P2.7** | **LCD1602 EN** | 输出 | 0 | `LCD_EN` |
| P1.0 | 电机 PWM 输出 → ULN2003 IN1 | 输出 | 低（电机停） | `MOTOR` |
| P1.5 | 蜂鸣器 | 输出 | 1（静音） | `BEEP` |
| P2.0 | LED 绿 | 输出 | 1（灭） | `LED_G` |
| P2.1 | LED 红 | 输出 | 1（灭） | `LED_R` |
| P3.0 | 串口 RXD | 输入 | — | 硬件固定 |
| P3.1 | 串口 TXD | 输出 | — | 硬件固定 |

> **注意 P1 上同时挂着 LCD、电机 PWM 和蜂鸣器。**
> Keil C51 里 `sbit MOTOR = P1 ^ 0;` 表示 P1 口的第 0 位，
> 写 `MOTOR = 1;` 会编译成一条 `SETB P1.0` 指令，**只动这一位**。
> 但如果你写 `P1 = 0x00;`（整口写），就会把 LCD 的数据线和电机、蜂鸣器一起冲掉。
> 所以本工程**所有 P1 上的操作都用 `sbit`，从来不整口写**。
>
> 这也是为什么在 200µs 的中断里要大量用 `sbit` —— 每条指令都要省。
>
> **附**：`firmware/legacy-smg/` 下保留了原来的数码管驱动（`smg.c` / `smg.h`），
> 如果想改回数码管显示，把它们加回工程并恢复 `render_display()` 即可，
> 接线不用动。
