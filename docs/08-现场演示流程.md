## B. 演示流程（约 6 分钟）

### 第 1 段 · 开场（30 秒）

**动作**：什么都不做。

> "这是一个**基于 51 单片机的自动温控散热系统**。
> DS18B20 实时测温度，和设定的目标比较，**自动把电机分成四个档位调速**。
> 全部用 C 写在一个 8KB 的单片机上，没有操作系统。"

### 第 2 段 · 静态展示（30 秒）

**动作**：手指依次点过去。

> "**DS18B20**（单总线温度传感器）、**ULN2003**（达朗顿驱动阵列——单片机 IO 只有 20mA，带不动电机）、**电机**、**液晶**。
>
> 第一行 `T= 27.3C` 是实测温度，`SET=35` 是目标；
> 第二行 `AUTO` 自动模式、`STOP` 当前状态、`P= 0` 占空比。
> 现在室温 27℃ 比目标 35℃ 低，所以**电机不转**。"

### 第 3 段 · 三个运行状态（2 分钟）★ 作业要求的"至少三种状态"

**① 自动停机** —— 什么都不做

> "**状态一：自动停机。** 温度比目标低 2℃ 以上，判定不需要散热，占空比 0%。"

**② 手动四档调速** ★ 全场最直观，一定要演

**动作**：短按 **K3** 一次（进手动模式）→ **连按 K4**（档位 0→1→2→3）

**现象**：液晶变 `MAN  HAND`；**每按一次 K4，电机明显快一档**

> "**状态二：手动四档调速。** 短按 K3 切手动，用 K4 切档——
> **注意听电机的声音，一档比一档快**。
>
> 8051 **没有硬件 PWM**，这是用定时器 0 每 200µs 中断做出来的**软件 PWM**，
> 50 级分辨率、100Hz。"

**③ 超温报警**

**动作**：串口发 `SIM T=45.0`

**现象**：整屏闪烁 + `AUTO ALARM  P=100` + **蜂鸣器急促** + **电机全速**

> "**状态三：超温报警。** 室温其实只有 27℃，我用串口**注入了 45℃ 的模拟温度**——
> 系统不知道是假的，照样判定超温，**强制全速 + 报警 + 闪屏**。
>
> 这个注入接口是我**专门为测试留的**：温度是慢变量，真烧一壶水来测不现实。
> 有了它，我的所有测试都**可复现**。"

**（等 5 秒）**

> "注意报警**不会立刻消失**——我设计了 5 秒锁存，防止临界点抖动导致报警闪烁。
> 现在它自己解除了。"

**恢复**：串口发 `RESET`

### 第 4 段 · 闭环：输入变化 → 自动响应（1.5 分钟）★ 核心要求

**动作 1**：串口发 `RESET` → **用手紧握 DS18B20 感温头**

**现象**：液晶温度**缓慢上升**（27.x → 28.x → 29.x…）

> "我用手给它加温——温度在上升。
> 系统每 100ms 判定一次，超过门限就**自动换档，不需要我按任何键**。"

**动作 2**：串口发 `SET T=22.0`

**现象**：室温 27℃ 立刻超过 22+3=25℃ 门限 → 液晶跳 `AUTO HIGH  P=100` → **电机自动全速**

> "换个方式：把**目标调到 22℃**，现在室温相对目标就是'过热'了——
> 看，系统**自己**从停机跳到全速。**这就是闭环**：
> 温度变化 → 判定 → 自动选择动作 → 电机响应，全程无人干预。"

**动作 3**：串口发 `SET T=60.0` → **电机自动停转**

> "反过来把目标调到 60℃，系统判定不需要散热，电机自己停。"

### 第 5 段 · 安全机制（1 分钟）★ 加分项

**动作**：**拔掉 DS18B20 的数据线**，等约 3 秒

**现象**：液晶 `T=  Err` + `AUTO FAULT  P=  0`；**电机强制停转**；红灯常亮 + **蜂鸣器长鸣**

> "**如果传感器坏了会怎样？** 我现在把传感器拔掉。（等）
>
> 看：**电机立刻停了**，液晶显示 `Err`，蜂鸣器长鸣。
>
> 这里的取舍是：**我不用最后一次的旧温度继续控制**。
> 因为'电机还在转、但温度是假的'会**掩盖故障**，比停机危险得多。
> 我的做法是**显式报错 + 主动停机**。
>
> 而且要求**连续 3 次**读失败（约 3 秒）才判故障，
> 避免杜邦线接触不良这种偶发干扰误触发。"

**动作**：插回数据线 → **自动恢复**

### 第 6 段 · 可重复性证据（30 秒）★ 作业要求的"多次重复验证"

**动作**：展示 [06-测试记录-自动生成.csv](06-测试记录-自动生成.csv)

> "作业要求'通过多次重复的实测来验证'。这是 **270 条**记录——18 个用例 × 3 轮 × 5 次重复。
>
> 关键两个数：**回差抖动**，门限附近抖动 100 次，没有回差的设计切换 **100 次**，我的只切换 **1 次**；
> **模糊测试** 5000 组随机用例，**0 处违规**。
>
> 而且这些不是我手工记的——控制逻辑我在 PC 上做了**等价仿真**，
> 阈值直接读 `config.h`、和固件**同源**，所以仿真结论对实物有效。"

### 第 7 段 · 收尾（20 秒）

> "总结：**输入**是温度变化和按键，**判断**是四档阶梯回差，**输出**是 PWM 调速的电机。
> 三个状态——停机、四档调速、超温报警——都能稳定复现。
> 代码 **6322 字节，占 8KB Flash 的 77%**。谢谢老师。"

## C. 三个"万一"的应急预案

| 万一 | 现象 | 现场处理 |
|---|---|---|
| **液晶花了** | 空白或黑方块 | 先旋对比度电位器（板上 **RJ1**）。还不行就**全程用串口帧代替液晶**讲——帧里有温度、档位、占空比、状态，信息一点不少 |
| **电机不转** | 切到 100% 也没动静 | ① 确认一根线在 **+5V**、另一根在 **OUT1**；② 查 **P1.0→IN1 的跳线帽**；③ 还不行就只讲串口里的占空比，说明"驱动电路已实测通过" |
| **串口收不到** | 串口助手空白 | ① 换 USB 口；② 确认波特率 **9600**；③ 关掉其它占用串口的软件。**实在不行纯靠按键+液晶演示**，第 3、5 段完全不需要串口 |

> **提前演练**：至少走两遍，第二遍**故意拔掉液晶**，练习"没有液晶也能讲完"。

## 0. 演示前必须先背下来的 12 个数字

| 项目 | 数值 | 出处（config.h） |
|---|---|---|
| 晶振 | 11.0592MHz（波特率误差 0） | `FOSC_HZ 11059200UL` |
| 串口 | 9600 8N1 | 第 5 节注释 |
| PWM 中断周期 | 200µs（定时器 0） | `PWM_ISR_US 200` |
| PWM 级数 | 50 级 → 周期 10ms → **100Hz** | `PWM_LEVELS 50` |
| 四档占空比 | STOP 0 / LOW 17(34%) / MID 33(66%) / HIGH 50(100%) | `DUTY_STOP/LOW/MID/HIGH` |
| 默认目标温度 | 35.0℃（Tset=350） | `TSET_DEF 350` |
| 目标温度可调范围 | 20.0℃ ~ 60.0℃，每次 ±1.0℃ | `TSET_MIN 200` / `TSET_MAX 600` / `TSET_STEP 10` |
| 升档阈值 | 低速 T≥Tset−2.0℃；中速 T≥Tset；全速 T≥Tset+3.0℃ | `LV_ENTER_LOW/MID/HIGH` |
| 降档阈值 | 低速退 T≤Tset−4.0℃；中速退 T≤Tset−2.0℃；全速退 T≤Tset+1.0℃ | `LV_EXIT_LOW/MID/HIGH` |
| 报警阈值 | 进 T≥Tset+8.0℃；出 T≤Tset+4.0℃ 且保持 ≥5s | `ALARM_OFFSET 80` / `ALARM_EXIT 40` / `ALARM_HOLD_MS 5000` |
| 采样 / 转换 | 采样周期 1000ms；转换等待 800ms（12 位需 750ms，留余量） | `DS_SAMPLE_MS 1000` / `DS_CONV_MS 800` |
| 故障判定 | 连续读失败 **3** 次 → FAULT | `DS_FAIL_LIMIT 3` |

补充数字：状态判定 100ms（`TICK_MS`）、显示刷新 200ms（`OLED_MS`）、串口上报 1000ms（`LOG_MS`）、按键扫描 20ms（`KEY_SCAN_MS`）、消抖 40ms（`KEY_DEBOUNCE_MS`）、长按 1500ms（`KEY_LONG_MS`）、跳变短鸣 60ms（`BEEP_TICK_MS`）、报警节奏 150ms 响/150ms 停（`ALARM_ON_MS` / `ALARM_OFF_MS`）。

**8 种状态**：`INIT`(0) / `STOP`(1) / `LOW`(2) / `MID`(3) / `HIGH`(4) / `ALARM`(5) / `FAULT`(6) / `MANUAL`(7)。

## 1. 演示前 5 分钟检查清单

**原则：先检查"能不能演示"，再检查"演示得好不好看"。每一行都要真的动手做一遍，不要靠记忆。**

### 1.1 上电与下载顺序（照做，不要跳）

- [ ] 把开发板 USB 线插到**电脑后置 USB 口**（前置口供电差，容易导致下载失败或复位）
- [ ] 打开 STC-ISP，选对 **COM 口**（设备管理器里确认是哪个，拔插一次看哪个消失）
- [ ] 单片机型号选 **STC89C52RC**，晶振填 **11.0592**
- [ ] 打开 `firmware` 工程编译出的 `.hex` 文件
- [ ] **先点 STC-ISP 的"下载/编程"按钮，再给板子冷启动**（关电源开关再开，或拔插 USB）——这一步错了必然握手失败
- [ ] 看到 "操作成功" 后再进入下一步
- [ ] 全程**板子保持水平**，杜邦线用胶带或扎带固定，避免演示中途松动

### 1.2 五项功能体检表

| # | 检查项 | 怎么查（30 秒内） | 合格标准 | 不合格就做 |
|---|---|---|---|---|
| 1 | 上电顺序 / 供电 | 目视 + 摸一下稳压芯片温度 | 板载电源灯亮，芯片不烫手 | 换 USB 口或换一根粗线；电机不要从板载 5V 大电流取电 |
| 2 | Keil 下载 | 看 STC-ISP 提示 | 显示"操作成功"，不是"握手失败" | 冷启动重来；COM 口重选；关掉占用的串口助手再下载 |
| 3 | 串口助手参数 | 看串口助手状态栏 | **COM 口正确 / 9600 / 8 / 无校验 / 1 停止位**，接收区每 1s 出现一帧 | 波特率错会全乱码；勾了"16 进制显示"会看不懂，取消它 |
| 4 | 数码管是否亮 | 上电看 | 8 位全亮，显示当前温度（如 `25.0`）和目标温度 | 不亮查 P0 段选排线 + 74HC245；乱码查位选 P2.2/P2.3/P2.4 |
| 5 | DS18B20 是否读得到 | 看串口帧最后一位 `SENSOR` | 显示 `OK` | 显示 `NOPRESENT`/`BADCRC` → 检查 4.7k 上拉到 **+5V**、按压 DQ 线，见第 7 节 |
| 6 | 电机是否受控 | 串口发 `MODE MANUAL` 再发 `LEVEL 0` 然后 `LEVEL 3` | 停 → 全速（能听到明显的转速差） | 见第 7 节"电机不转"一行 |

### 1.3 兜底方案：DS18B20 坏了也能照常演示（务必提前练一次）

- [ ] 演示前**故意拔掉 DS18B20**，确认程序能进 `FAULT` 状态，且电机停转
- [ ] 确认串口助手可以正常发命令：发 `STATUS`，**应当立刻回一帧**（不等 1s）
- [ ] **兜底操作口诀**：传感器一坏，全程改用 `SIM` 注入温度 + `LEVEL` 直接给档
  - `SIM T=25.0` → 演示 STOP 停机
  - `SIM T=34.0` → 演示 LOW 低速（Tset=350，进入条件 T≥330）
  - `SIM T=35.0` → 演示 MID 中速
  - `SIM T=38.5` → 演示 HIGH 全速
  - `SIM T=45.0` → 演示 ALARM 报警
  - `MODE MANUAL` + `LEVEL 0/1/2/3` → 演示手动四档
  - 真传感器修好了就用 `SIM OFF` 切回真实测温
- [ ] 兜底话术提前想好："真实传感器我现场演示，仿真模式是给自动化测试用的，下面我用注入的方式把每一种状态再走一遍，保证不漏状态。"

### 1.4 电脑侧准备

- [ ] 串口助手（SSCOM / 友善串口）预先打开，波特率、串口号配好，**发送新行（换行）已勾选**
- [ ] 把常用命令做成"快捷发送按钮"：`STATUS` / `SIM T=45.0` / `SIM T=25.0` / `SIM OFF` / `MODE MANUAL` / `LEVEL 3` / `RESET`——**现场手打命令是最大失分点**
- [ ] 手机开飞行模式或放远一点（来电会让 USB 供电波动）
- [ ] 提前把本文第 3 节的演示脚本打印一份放手边

### 2.2 三分钟极简版（老师只给 3 分钟时）

| 时间 | 动作 | 一句话 |
|---|---|---|
| 0:00–0:20 | 上电，指串口帧 | "每 1s 一帧，10 个字段，温度、目标、档位、占空比、状态全在这" |
| 0:20–0:50 | K4 连按到 Tset=20.0℃ | "不用加热，改目标温度就能看全速" → HIGH |
| 0:50–1:15 | 串口 `SIM T=45.0` | "报警：红灯 + 蜂鸣器 150ms 节奏，电机 100%" |
| 1:15–1:40 | 串口 `MODE MANUAL` + `LEVEL 0/1/2/3` | "手动模式，档位可以硬指定 0~3" |
| 1:40–2:15 | 拔 DS18B20 数据线 | "连续 3 次读失败 → FAULT，电机强制停转" |
| 2:15–2:45 | 插回 + `RESET` | "恢复默认参数、清报警" |
| 2:45–3:00 | 亮出 `config.h` | "所有引脚和参数集中在一个头文件，换板子只改这一份" |

## 3. 六种以上运行状态的完整演示脚本

> 统一结构：**状态名 → 怎么触发（物理 / 串口两条路）→ 预期现象 → 一句讲解词**
> 默认前提：Tset = 35.0℃（350），室温约 25℃。

### 3.1 STOP 停机

- **状态**：STOP 停机（串口 `ST` 字段 = `STOP`，`ST` 编号 1）
- **怎么触发**
  - **物理**：什么都不用做。室温约 25℃，只要 **T ≤ Tset−4.0℃ = 31.0℃**，系统就停在 STOP。如果刚才演示过加热，等它自然降到 31.0℃ 以下，或用湿纸巾贴感温头辅助降温。
  - **串口**：`SET T=45.0`（把目标温度拉到 45.0℃，室温立刻低于 Tset−4.0℃），或 `SIM T=25.0` 注入室温。
- **预期现象**
  - 数码管：显示当前温度（如 `25.0`）与目标温度
  - LED：**绿灯亮**（正常待机）
  - 蜂鸣器：不响（跳变瞬间有 **60ms** 短鸣）
  - **电机：完全不转**（`DUTY=0`，占空比 0%，P1.0 输出低）
  - 串口帧：`$S,<ms>,250,450,0,0,STOP,AUTO,0,0,OK`
- **讲解词**："室温 25.0℃ 低于目标温度 4℃ 以上，不需要散热，档位 0，占空比 0%，电机彻底断电，不是低速空转。"

### 3.2 LOW 低速

- **状态**：LOW 低速（`ST` = `LOW`，编号 2，`LEVEL=1`）
- **怎么触发**
  - **物理**：用手握住 DS18B20 感温头 10 秒左右（手温约 33~35℃），把温度推到 **T ≥ Tset−2.0℃ = 33.0℃**；不够就用手掌捂住整个传感器，或用吹风机隔 20cm 吹 5~8 秒。
  - **串口**：`SIM T=34.0`。
- **预期现象**
  - 数码管：`34.0`
  - LED：**绿灯亮**
  - 蜂鸣器：跳变瞬间短鸣 **60ms** 一声
  - **电机：明显慢速转动（占空比 34%，即 PWM 50 级里的 17 级），能用手轻捏住停住**
  - 串口帧：`$S,<ms>,340,350,1,34,LOW,AUTO,0,0,OK`
- **讲解词**："温度刚越过目标温度下 2℃，进入低速档，占空比 34%。这时候还只是轻微发热，不需要全速吹。"

### 3.3 MID 中速

- **状态**：MID 中速（`ST` = `MID`，编号 3，`LEVEL=2`）
- **怎么触发**
  - **物理**：继续用手捂感温头 / 吹风机再吹 5 秒，让 **T ≥ Tset = 35.0℃**。
  - **串口**：`SIM T=35.0`。
- **预期现象**
  - 数码管：`35.0`
  - LED：**绿灯亮**
  - 蜂鸣器：跳变瞬间 60ms 短鸣
  - **电机：转速明显上一台阶（占空比 66%，PWM 33 级）**
  - 串口帧：`$S,<ms>,350,350,2,66,MID,AUTO,0,0,OK`（config.h 里给的示例帧就是这个）
- **讲解词**："到目标温度了，中速档，占空比 66%。到这里注意：如果我把它降到 34.0℃，它**不会**马上下低速，要降到 Tset−2.0℃ = 33.0℃ 才降档——这就是回差。"

### 3.4 HIGH 全速

- **状态**：HIGH 全速（`ST` = `HIGH`，编号 4，`LEVEL=3`）
- **怎么触发**
  - **物理**：吹风机隔 20cm 吹到 **T ≥ Tset+3.0℃ = 38.0℃**；或直接用马克笔对感温头哈气不行——用热风最快。
  - **串口**：`SIM T=38.5`。
  - **★ 一键法**：按 K4 把 Tset 从 35.0℃ 按到 20.0℃，室温 25℃ 立刻 ≥ Tset+3.0℃ = 23.0℃，**直接从 STOP 跳 HIGH**，详见第 4 节。
- **预期现象**
  - 数码管：`38.5`
  - LED：**绿灯亮**（还没到报警）
  - 蜂鸣器：跳变瞬间 60ms 短鸣
  - **电机：全速（占空比 100%，P1.0 恒为高电平，ULN2003 持续导通）**
  - 串口帧：`$S,<ms>,385,350,3,100,HIGH,AUTO,0,0,OK`
- **讲解词**："超过目标温度 3℃，全速散热。注意 100% 占空比时软件 PWM 退化成直流导通，效率最高。"

### 3.5 ALARM 报警

- **状态**：ALARM 报警（`ST` = `ALARM`，编号 5）
- **怎么触发**
  - **串口（最稳）**：`SIM T=45.0` —— 45.0℃ ≥ Tset+8.0℃ = 43.0℃，直接进报警。
  - **物理**：吹风机贴近吹到 **T ≥ 43.0℃**（注意别把塑料壳吹变形，感温头留 1~2cm 距离）。
  - **一键法**：先 `SET T=30.0` 再 `SIM T=45.0` 效果更直观（阈值差 15℃）。
- **预期现象**
  - 数码管：`45.0`
  - LED：**红灯亮（报警色）**
  - 蜂鸣器：**150ms 响 / 150ms 停 的连续急促节奏**（`ALARM_ON_MS` / `ALARM_OFF_MS`）
  - **电机：100% 全速强制散热**
  - 串口帧：`$S,<ms>,450,350,3,100,ALARM,AUTO,1,1,OK`（`BUZ=1`）
  - **解除条件**：降到 **≤ Tset+4.0℃ = 39.0℃**，且报警已保持至少 **5 秒**（`ALARM_HOLD_MS 5000`）才解除。发 `SIM T=38.0`，数 5 秒，报警消失。
- **讲解词**："超过目标 8℃ 报警：红灯 + 蜂鸣器 + 全速散热三件事同时做。解除要回到目标 +4℃ 并且保持 5 秒，防止在阈值上来回抖，蜂鸣器哒哒哒响个不停。"

### 3.6 FAULT 传感器故障保护

- **状态**：FAULT 传感器故障保护（`ST` = `FAULT`，编号 6）
- **怎么触发**
  - **物理（最有说服力）**：**直接把 DS18B20 的数据线（DQ）拔掉**。采样周期 1s，**连续 3 次读失败 → 约 3 秒后**进 FAULT。拔电源线不行（那叫断电），要拔数据线。
  - **物理备选**：把 4.7k 上拉电阻一端拔掉，DQ 悬空读不到 → 同样进 FAULT。
  - **串口**：无法直接注入 FAULT（探针是真实的 1-Wire 读取），但可以发 `STATUS` 观察 `SENSOR` 字段从 `OK` 变成 `NOPRESENT`。仿真模式（`SIM`）下传感器探针仍在后台跑，**仿真只替换温度值，不屏蔽故障检测**——这一点要主动讲出来，是加分项。
- **预期现象**
  - 数码管：显示 `Err` 或温度字段失效提示（不再显示假温度）
  - LED：**红灯亮**
  - 蜂鸣器：短鸣一声提示
  - **电机：强制停转（占空比 0）——即使拔线前正在全速转，也必须立刻停**
  - 串口帧：`$S,<ms>,0,350,0,0,FAULT,AUTO,0,0,NOPRESENT`（`SENSOR` 字段报 `NOPRESENT`／`BADCRC`／`NOINIT`）
- **讲解词**："传感器坏了，我宁可停机也不瞎转。因为**最后一次温度是不可信的**——可能是传感器卡在 60℃ 导致电机一直全速，也可能是卡在 20℃ 导致该散热的时候不散热。停机是可解释的安全状态，瞎转不是。"

### 3.7 MANUAL 手动

- **状态**：MANUAL 手动（`ST`/`MODE` 报 `MANUAL`，编号 7，`MODE=MANUAL`）
- **怎么触发**
  - **物理**：**短按 K3（P3.2）** 一次 → 自动切手动；再短按切回自动。进入手动后用 **K4（P3.3）短按切档**：0→1→2→3→0 循环。
  - **串口**：`MODE MANUAL`，然后用 `LEVEL 0` / `LEVEL 1` / `LEVEL 2` / `LEVEL 3` 直接指定档位。
- **预期现象**
  - 数码管：显示当前档位/温度，**MODE 字段变 `MANUAL`**
  - LED：绿灯亮（手动不是报警态）
  - 蜂鸣器：切换瞬间 60ms 短鸣
  - **电机**：`LEVEL 0` 停 / `LEVEL 1` 34% / `LEVEL 2` 66% / `LEVEL 3` 100%，与自动模式完全一致
  - 串口帧：`$S,<ms>,250,350,3,100,MANUAL,MANUAL,0,0,OK`
- **讲解词**："手动模式是为了**调试和验证执行机构**用的——自动控制逻辑我不想动，但我要能单独确认电机四档都能转。这也是我给串口设计 `LEVEL` 命令的原因。"

## 4. "一键演示"技巧（重点）

> 核心思想：**作品的被控量是"温度与目标温度的差"，所以改目标温度与改温度是等价的，而按按键比加热快 100 倍。**
> 默认 Tset = 35.0℃，室温约 25℃。每按一次 K4，Tset 变化 `TSET_STEP = 10`，即 **1.0℃**；范围限幅在 20.0~60.0℃。

### 4.1 技巧一：按 K4 把 Tset 从 35.0℃ 一路按到 20.0℃ → 室温 25℃ 立刻全速

- 操作：连续短按 K4 **15 次**（35.0 → 20.0℃，每次 1.0℃）
- 判定：T = 25.0℃ ≥ Tset+3.0℃ = 20.0+3.0 = **23.0℃** → 进 HIGH
- 效果：**STOP 直接跳到 HIGH**，数码管目标值显示 `20.0`，电机 100% 全速
- 讲解词："我没有加热，只是把'觉得热'的标准降低了——系统认为 25℃ 已经超标 5℃，于是全速散热。这就是温控系统里'目标温度'这个参数的作用。"
- 时间成本：**约 5 秒**（对比：用吹风机加热到 38℃ 至少 30 秒，还不稳定）

### 4.2 技巧二：反过来按到 60.0℃ → 电机立刻停转

- 操作：从 20.0℃ 继续按 K4 到 60.0℃（40 次），或先 `SET T=60.0` 一步到位
- 判定：T = 25.0℃ ≤ Tset−4.0℃ = 60.0−4.0 = **56.0℃** → 回 STOP
- 效果：**电机立刻停转**，占空比 0%
- 讲解词："反过来也一样。目标调到 60℃，室温 25℃ 差得远，系统判定'完全不热'，电机断电。"
- **技巧**：现场时间紧就用串口 `SET T=60.0`，一条命令搞定，避免按 40 次按键

### 4.3 技巧三：串口发 `SIM T=45.0` → 直接触发报警

- 操作：串口助手发一行 `SIM T=45.0`（**以换行结尾**）
- 判定：45.0℃ ≥ Tset+8.0℃ = 43.0℃ → ALARM
- 效果（一秒内全部发生）：
  - 红灯亮
  - 蜂鸣器 150ms 响 / 150ms 停
  - 电机 100%
  - 串口帧 `BUZ=1`、`SIM=1`、`ST=ALARM`
- 解除：发 `SIM T=38.0`（≤ 39.0℃），**等够 5 秒**报警解除
- 讲解词："`SIM` 是我为讲解和自动化测试做的注入接口，它绕过传感器但**走在完全相同的控制路径上**——状态机、回差、报警、PWM 一个都不少。这也是我能把 8 个状态全部演示一遍的原因。"
- **别忘了**：演示完发 `SIM OFF` 回到真实传感器，否则后面的物理演示看不出效果

### 4.4 技巧四：拔掉 DS18B20 的数据线 → 约 3 秒进 FAULT，电机强制停转

- 操作：**在电机正在全速转的时候**拔掉 DQ 数据线
- 判定：采样周期 `DS_SAMPLE_MS = 1000`ms，连续 `DS_FAIL_LIMIT = 3` 次失败 → 约 **3 秒**进 FAULT
- 效果：**电机从全速瞬间变成停转**，红灯亮，串口 `SENSOR=NOPRESENT`
- 讲解词："这个演示最有说服力：我用一根线把'正在散热的系统'变成了'保护状态'，而且是以**停机**而不是**继续转**的方式保护。"

### 4.5 一键演示安全边界（老师可能追问）

- 按 K4 到 60.0℃ 后再按不会超过 60.0℃（`TSET_MAX 600` 限幅）
- 按到 20.0℃ 后再按不会低于 20.0℃（`TSET_MIN 200` 限幅）
- **K3 长按 1.5s（`KEY_LONG_MS 1500`）→ 恢复默认**：Tset 回 35.0℃、退出仿真、清除报警，一条龙复位。这个动作用来"回到演示起点"最好使。
- 串口 `RESET` 与 K3 长按等效，但更可控

## 5. 为什么"电机停转"是安全设计

被问到时这一节要主动讲，不要等老师问。

1. **故障时"最后一次温度"是不可信数据。** DS18B20 失效有三种典型表现：读回 85.0℃（上电默认值）、读回 0.0℃、CRC 校验失败。前两种都会让控制逻辑得到完全错误的结论——85.0℃ 会让电机一直 100% 空转烧电机，0.0℃ 会让该散热的时候完全不动。**用一个已知错误的数据去驱动执行机构，比不驱动更危险。**
2. **停机是"可解释状态"，瞎转不是。** FAULT 状态下数码管、红灯、串口三处都明确告诉使用者"传感器坏了"，人能立刻处理；而"电机还在转但温度是假的"会掩盖故障，让人以为系统正常。
3. **电机堵转/空转都有代价。** 5V 小电机长期堵转电流可达几百 mA，经 ULN2003 和板载 5V 取电时会把电源电压拉低，串联故障可能导致单片机复位（见文档 09 的问题 4），故障会扩散。
4. **这是嵌入式安全设计的基本范式**：`fail-safe`（故障导向安全）。工业温控里对应的做法是"传感器断线时切断加热输出"，本项目对应的是"传感器断线时切断电机输出"。方向一致：**执行器在信息不可靠时必须回到不动作的默认位。**
5. **停转是可恢复的，且恢复条件明确。** 插回传感器后连续读取成功即退出 FAULT；`RESET` 或 K3 长按可以强制恢复默认。相当于一个软件看门狗。

**一句话总结（背下来）**："有温度我按温度控制，没温度我按安全控制。信息不可靠时，执行机构必须回到不动作状态。"

## 6. 讲解提问预案（18 问）

### Q1. 51 没有硬件 PWM，你的 PWM 是怎么做出来的？

**答**：用定时器 0 做软件 PWM。定时器 0 每 **200µs**（`PWM_ISR_US`）中断一次，中断里对一个 0~49 的计数器加一，计到 50 清零，这样得到 **10ms** 的 PWM 周期，也就是 **100Hz**。每个中断里把计数器与当前档位对应的占空比级数比较（`DUTY_STOP 0` / `DUTY_LOW 17` / `DUTY_MID 33` / `DUTY_HIGH 50`），小于就输出高、否则输出低，写 P1.0 即可。

定时器初值按 11.0592MHz 晶振算：**一个机器周期 = 12 / 11.0592MHz ≈ 1.085µs**，200µs 约合 **184.3 个机器周期**，所以定时器 0 的重装值取 **65536 − 184 ≈ 65352（0xFF48）**。中断里只做"计数 + 比较 + 写一个 IO"，几条指令，绝不会超出 184 个机器周期的预算。

**加分补充**：50 级、100Hz 是我权衡出来的。级数太少（比如 8 级）转速台阶太粗，低速档会一顿一顿；频率太高（比如 1kHz）在 200µs 中断里软件开销占比上升，而且 5V 小电机在低频段反而转矩更好。100Hz 听不到明显啸叫，转速也平滑。

### Q2. 为什么用阶梯回差（迟滞）而不是简单阈值？

**答**：单阈值的问题是**临界点抖动**。如果只有"T ≥ Tset 就转、T < Tset 就停"一条线，温度在 35.0℃ 附近受气流影响上下抖 0.5℃，状态机就会在 1 秒内启停十几次——机械冲击大、噪声大、电机和驱动管寿命都会下降。所以我给每个档位都设计了**双阈值**：进档和退档用不同的阈值，中间留死区。

**具体数字**（可直接写在黑板上）：
| 档位 | 进档条件 | 退档条件 | 死区 |
|---|---|---|---|
| LOW | T ≥ Tset−2.0℃ | T ≤ Tset−4.0℃ | 2.0℃ |
| MID | T ≥ Tset | T ≤ Tset−2.0℃ | 2.0℃ |
| HIGH | T ≥ Tset+3.0℃ | T ≤ Tset+1.0℃ | 2.0℃ |

报警也是同样思路：进 T ≥ Tset+8.0℃，出 T ≤ Tset+4.0℃ 且保持至少 5 秒。

### Q3. 为什么不用浮点数？

**答**：三个原因。第一，**慢**——8051 是 8 位机，没有 FPU，一个 float 乘除要走软件浮点库，几百个时钟周期起步，而我有 200µs 的中断和 1s 的采样周期，Flash 和时间都耗不起。第二，**占空间**——浮点库本身会吃掉相当一部分 Flash，而 Keil 未注册版有 **2KB 代码限制**，这是硬约束。第三，**没必要**——DS18B20 的 12 位分辨率是 0.0625℃，我只需要 0.1℃ 的显示精度，所以我把温度统一用**定点数**表示：单位 0.1℃，**350 就表示 35.0℃**。加减比较全是整数运算，显示时直接拆位送数码管，一位除法都不用。

### Q4. DS18B20 的 1-Wire 时序你是怎么保证的？

**答**：分两类延时治。**短延时用 `_nop_()` 精确凑**——读时隙要求在主机拉低总线后 **约 11µs** 采样从机数据，我就用几个 `_nop_()` 拼出这个窗口，保证在时序容差最紧的地方不飘。**长延时用循环凑但给足余量**——复位脉冲拉低 480µs 以上、写 1 时隙拉低约 10µs 后释放、写 0 时隙拉低约 100µs 再释放，这些量的容差是几十µs 级，普通循环延时完全够，而且我把采样点放在窗口中部而不是边缘，抗干扰余量大。另外 DQ 是准双向口，读之前先写 1 释放总线，读一个时隙后再释放，不能夹着写操作。

### Q5. 为什么读温度要等 750ms？这期间程序在干什么？

**答**：**转换发生在 DS18B20 芯片内部，不是主机在算**，所以这 750ms 里 1-Wire 总线是空闲的，主机完全可以干别的事。我留的等待时间是 `DS_CONV_MS = 800`ms（750ms + 余量）。而且我**没用 `delay(800)` 死等**——主循环是**非阻塞时间片调度**：温度采样、状态机判定（100ms）、显示刷新（200ms）、串口上报（1000ms）各自按时间戳轮询；**PWM（200µs）和数码管扫描都在定时器中断里**，跟主循环完全解耦。所以这 800ms 里数码管照样在扫、电机照样在调速，按键也照样响应。这也是我踩过的坑：早期版本用死延时，结果按键要按住很久才有反应（见文档 09 问题 9）。

### Q6. 电机为什么不能直接接 51 的 IO 口？

**答**：**电流不够**。51 的 IO 口单脚**灌电流约 20mA**（拉电流更小），而 5V 小电机启动瞬间要**几百 mA**，正常工作也在 100mA 量级。直接驱动有两个后果：一是电机根本不转或转得很勉强，二是大电流经端口灌入会烧 IO 口甚至整片单片机。所以我用 **ULN2003** 达林顿阵列做低边驱动，它是一个电流放大器兼开关，单片机只管给控制信号，功率电流走 ULN2003 自己的回路。

### Q7. 为什么电机用 P1.0 接 ULN2003？ULN2003 是反相的，你怎么处理？

**答**：P1.0 是普通 IO，没有第二功能冲突（P3.0/P3.1 要给串口、P3.2/P3.3 给按键、P3.7 给 DS18B20），所以拿它最省事。反相确实是关键点：**ULN2003 的 IN 给高电平，内部达林顿管导通，OUT 被拉到接近 0V，此时负载才通电**——也就是说"IN 高 = 电机转"。

我的处理方式是在 `config.h` 里**把反相这件事封死在宏里**：

```c
sbit MOTOR = P1 ^ 0;
#define MOTOR_ON   1      /* ULN2003 反相 → IN 高 → OUT 拉低 → 电机通电 */
#define MOTOR_OFF  0
```

上层代码只写 `MOTOR = MOTOR_ON/OFF`，**PWM 中断里也是按"高=通电"的直觉写的**，反相逻辑只在这三行里体现一次。这样既避免了满代码里散布 `!` 取反（那种写法最容易在改占空比时漏掉一处），也顺便定了极性。另一个必须讲清的点：**负载要接在 +5V 和 ULN2003 的 OUT 之间，不能接在 GND 和 OUT 之间**——低边驱动的 OUT 是"拉到地"的开关，接错了电机永远不转（见文档 09 问题 3）。

### Q8. 温度采集周期为什么是 1 秒？

**答**：三个约束凑出来的。第一，DS18B20 转一次就要 750ms，采样周期不可能短于它，否则读回来的还是上一次的结果。第二，**温度是慢变量**——空气和被测物的热惯性以秒计，1s 采一次完全跟得上，采样再快也只是重复读同一个数字，白白浪费 CPU 时间。第三，1s 正好和我的**串口上报周期一致**（`LOG_MS 1000`），一帧数据对应一次采样，日志看起来最直观。所以我定 `DS_SAMPLE_MS = 1000`、`DS_CONV_MS = 800`。

### Q9. 你的蜂鸣器为什么在状态跳变时要短鸣一声？

**答**：这是**给使用者的听觉反馈**，也是我的调试手段。`BEEP_TICK_MS 60` 一声短鸣，只在状态真正发生变化时响——因为温度是慢变量，状态一秒内可能变好几次（尤其在有回差死区之前），**"每变一次响一声"直接把控制逻辑的跳变行为变成了可听见的节奏**。演示现场我用它证明"刚才那一下确实换档了"，比盯着数码管快。报警则用另一套节奏：`ALARM_ON_MS 150` / `ALARM_OFF_MS 150`，急促的哒哒声和普通短鸣区分得很清楚。

### Q10. 传感器故障保护是怎么实现的？

**答**：分三层。**第一层是读取层**——1-Wire 读取有明确的失败出口：器件无应答报 `NOPRESENT`、CRC 校验错报 `BADCRC`、初始化失败报 `NOINIT`，这三种都算一次"读失败"，成功才报 `OK`，并且这个结果会出现在串口帧的 `SENSOR` 字段里，方便定位。**第二层是计数层**——`DS_FAIL_LIMIT = 3`，**连续 3 次失败**（也就是约 3 秒）才判故障，避免一次偶发干扰就误触发。**第三层是动作层**——进 `FAULT` 后电机**强制停转**（占空比 0），红灯亮，数码管提示错误，不再使用任何温度值。插回传感器后连续读成功即自动退出。**为什么是 3 次而不是 1 次**：杜邦线接触不良、旁边有电机干扰，都可能造成一次偶发失败；3 次是"偶发"和"真断线"的分界。

### Q11. 两个按键怎么实现这么多功能？

**答**：靠**短按/长按 + 模式区分**两个维度组合。底层按键扫描放在**定时器中断里每 20ms 一次**（`KEY_SCAN_MS`），连续两次（40ms，`KEY_DEBOUNCE_MS`）读到同电平才确认，按住超过 1500ms（`KEY_LONG_MS`）判长按。在这个基础上：

| 按键 | 引脚 | 短按 | 长按 1.5s |
|---|---|---|---|
| K3 (SET) | P3.2 | 自动 ↔ 手动 切换 | 恢复默认（Tset=35.0℃、退出仿真、清报警） |
| K4 (UP) | P3.3 | 自动模式：Tset +1.0℃；手动模式：档位 0→1→2→3 循环 | （本项目未定义，保留） |

所以 2 个按键实际给出 4 个功能，再叠加"自动/手动"两种语境，一共能覆盖 6 种操作。**为什么按键放在 P3.2/P3.3**：P3.0/P3.1 是串口 RXD/TXD，我要留出来做串口自动化测试，不能被按键占用。

### Q12. Keil C51 未注册版有 2KB 代码限制，你怎么处理的？

**答**：三条路，我走的是第三条为主。**第一，注册**（有正版授权就直接解决，但课程环境不一定有）。**第二，改用 SDCC**（开源免费无限制，代价是语法/库和 Keil 有差异，需要改工程）。**第三，裁剪代码**——这是我在做的：
- **关掉 `printf`**：Keil 的 printf 会拖进一大坨格式化代码，我改成手写的串口发送 + 定点拆位，只发我需要的 10 个字段；
- **用 `code` 关键字把常量表放 ROM**：数码管段码表、状态名字符串表全部声明成 `code`，只占 Flash 不占宝贵的 RAM；
- **少用浮点**（见 Q3），省下整个浮点库；
- **函数不滥用内联、重复逻辑合并**，中断服务程序尽量短。

**加分说法**："2KB 限制其实是好事——它逼我把每一字节都想清楚，最后我的代码是典型的 8 位机写法：定点数、查表、位操作、状态机，没有一处'反正空间够'的浪费。"

### Q13. 这个系统还能怎么改进？

**答**：见文档 09 最后一节，我在那里写了 5 条。现场挑 2~3 条讲：
1. **换带硬件 PWM 的芯片**（STC15 / N76E003 有 PCA/PWM 模块），把 200µs 中断从 CPU 上卸下来，主循环余量更大、PWM 精度更高；
2. **加 NTC 做冗余测温**，两路温度交叉校验——两路差超过阈值就判传感器可疑，比单传感器可靠；
3. **参数存 EEPROM**（STC89C52RC 有片内 EEPROM），Tset、回差、报警阈值掉电不丢，不用每次上电重新设；
4. **换成旋转编码器**代替两个按键，调温度不用按 15 次；
5. **加 I2C OLED** 显示温度曲线，比数码管直观得多。

### Q14. 你的设计和市面上的温控风扇有什么区别？

**答**：市面上的温控风扇（包括机箱风扇、部分电风扇）**大多只有一档或两档**——到某个温度就转，或者低/高两档，本质是"阈值开关"。我的区别在四点：
1. **四档阶梯 + 每档双阈值回差**，转速不是"跳变"而是"有台阶地过渡"，转速变化跟热量变化更匹配，也不会在临界点疯狂启停；
2. **有故障安全逻辑**：市面产品传感器坏了往往就是"不转"或"狂转"，我这里是显式的 `FAULT` 状态 + 主动停机 + 三处提示（数码管/红灯/串口）；
3. **有手持调试与上位机接口**：串口 10 字段遥测 + 6 条控制命令 + 仿真注入模式，能自动化测试、能远程改参数——这是"产品"和"教学作品"的差别；
4. **参数与逻辑分离**：所有引脚和控制参数集中在 `config.h`，换板子、改回差曲线只改一个头文件，这是面向复用的设计。

**一句话**："市面上的是'温度高了就吹'，我做的是'按温度分档吹、没温度不乱吹、还能把状态讲清楚'。"

### Q15. 如果传感器读数一直抖，你的系统会不会跟着抖？

**答**：不会，这是回差设计的目的（对应 Q2）。另外我有**三重抗抖**：一是档位双阈值死区 2.0℃；二是报警解除要 `ALARM_EXIT` 且保持 `ALARM_HOLD_MS = 5000` 至少 5 秒；三是**状态判定周期 100ms**（`TICK_MS`），不是中断里立刻改状态，天然有平均效果。真要更稳，还可以加一阶低通滤波（新值 = 旧值×0.7 + 采样值×0.3），定点实现只有几条指令。

### Q16. P0 口做数码管段选，为什么要加 74HC245？

**答**：P0 口是**开漏输出**，自己拉不出高电平，需要外部上拉才能输出高。数码管共阳是低电平点亮，看起来"只要拉低"就够了——但**位选由 74HC138 驱动、段选由 P0 驱动，两边要匹配电流**，而且 P0 悬空时数码管会乱亮。加 74HC245 做缓冲后，段选驱动能力确定，显示亮度均匀，也不会因为 P0 上拉不足导致某些段暗亮不一。这是普中板的标准接法，属于硬件层面必须讲清的一环。

### Q17. 为什么报警阈值是 +8.0℃，解除是 +4.0℃？这个数怎么定的？

**答**：`ALARM_OFFSET = 80`（+8.0℃）是"确实过温了"的判定，`ALARM_EXIT = 40`（+4.0℃）是"已经凉下来了"的判定，中间 4.0℃ 的死区再加 5 秒最短保持，保证报警**响起来就听得清、不来回抽**。定 8.0℃ 的依据是：我的正常控制带是 Tset−4℃ 到 Tset+3℃，全速档在 +3.0℃ 就已经触发了，留到 +8.0℃ 才报警，是让人先感受到"风扇已经全速工作"，再提示"这已经超出正常调节范围了"——分级响应，不是一到 +3℃ 就吓人。

### Q18. 这个工程的代码是怎么组织的？为什么强调 `config.h`？

**答**：**引脚和控制参数集中在一个 `config.h`**，其它 `.c` 文件不出现任何裸引脚号和魔法数字。好处有三个：一是**换板子只改一个文件**（晶振那行 `FOSC_HZ` 一改，定时器重装值和串口波特率全部自动重算）；二是**文档和代码不会走偏**——引脚表是从 `config.h` 派生的，改一处必须同步一处；三是**被问到时可讲**：控制参数的调优（回差、报警阈值、采样周期）全在一个文件里，是一条清晰的"参数—行为"链。

## 7. 现场翻车急救表

> 用法：症状出现 → 先看"最常见原因" → 做"30 秒处理"。**处理不了就切串口 `SIM` 兜底演示，先把流程走完。**

| # | 症状 | 最常见原因 | 30 秒内能做的处理 |
|---|---|---|---|
| 1 | 数码管完全不亮 | 段选排线松/插错（P0 经 74HC245）；供电不足；亮度电位器拧到底 | 重新按压 P0 排线和 74HC245，换 USB 口，转一下对比度电位器 |
| 2 | 数码管显示乱（笔画缺、闪烁） | 扫描刷新率太低 / 没有消隐；P0 上拉不足；杜邦线接触不良 | 确认代码在位选切换前先关段选（送 0xFF）；压紧排线；不行就只演示串口帧，温度照样读得到 |
| 3 | 数码管位序反了 | 74HC138 的 A/B/C 与 P2.2/P2.3/P2.4 对应关系与预期相反 | 把 `config.h` 的 `SMG_BIT_REVERSE` 从 `0` 改成 `1` 重新编译下载（30 秒改完，但下载要 40 秒——时间紧就先不修，口头说明） |
| 4 | 数码管只亮一位 / 8 位全亮不闪 | 74HC138 输入脚（P2.2/P2.3/P2.4）没接对；位选线断 | 检查 P2.2/P2.3/P2.4 三根线是否插在 74HC138 的 A/B/C 上；确认共阳位选极性 |
| 5 | 电机完全不转 | **ULN2003 输出接错**（负载接在 GND 与 OUT 之间）；P1.0 线没接；电机电源没接 | 立刻确认：电机一端接 **+5V**、另一端接 ULN2003 的 **OUT**（低边驱动，OUT 是拉到地的开关）；检查 P1.0 → IN1 |
| 6 | 电机一直全速转，不受控 | P1.0 接到 ULN2003 的错脚；或工作在 `MODE MANUAL` + `LEVEL 3`；或正在 ALARM | 串口发 `MODE AUTO` + `RESET`；再发 `LEVEL 0` 验证停转；确认 P1.0 接的是 IN1，不是别的 IN |
| 7 | DS18B20 读数恒为 **85.0** | **上电默认值**——转换没完成 / 读指令没成功 | 说明温度转换还没走完（12 位需 750ms，我留 800ms）；先等 1~2 个采样周期；再检查 4.7k 上拉和 DQ 接触；仍不行就 `SIM` 注入兜底 |
| 8 | DS18B20 读数恒为 **0** 或乱码 | 4.7k 上拉缺失、接到了 3.3V、杜邦线太长引入干扰 | 确认上拉电阻一端接 DQ、**另一端接 +5V**；换短杜邦线；降低走线长度；重新插拔传感器 |
| 9 | 按键没反应 | 按键线没插 K3(P3.2)/K4(P3.3)；误插到 K1/K2（P3.1/P3.0 是串口）；长按时间没到 1.5s | 确认插在 P3.2/P3.3；自动↔手动要**短按**，恢复默认要**按住 1.5s 以上**；也可用串口 `MODE`/`SET` 代替按键 |
| 10 | 串口乱码（接收区全是怪字符） | **晶振不是 11.0592MHz 而是 12MHz**（按 11.0592MHz 写死的重装值会让实际波特率偏约 **8.7%**）；波特率/校验位不匹配 | 串口助手改回 **9600 / 8 / 无校验 / 1 停止位**，并取消"16 进制显示"；若确认板子是 12MHz 晶振，改 `config.h` 的 `FOSC_HZ` 重新编译 |
| 11 | 串口一帧都不来 | 串口助手被别的程序占着（下载时会）；COM 口选错；TXD/RXD 接反（只影响外部模块，板载 USB 不受影响） | 用设备管理器确认 COM 号（拔插一次看哪个消失）；关掉 STC-ISP 再开串口助手（两者不能同时占串口） |
| 12 | 下载失败 / STC-ISP 握手失败 | **没冷启动**（必须先点下载再给板子上电）；下载时串口被助手占用 | 关掉串口助手 → 点"下载/编程" → **给板子断电再上电**；换 USB 口；降波特率（可选 9600→2400）重试 |
| 13 | 下载成功但程序不运行 | 上电后没复位；电源跌落导致反复复位；烧错了 hex | 手动按一次复位键；拔掉电机再上电看是否正常（电机大电流拉低电源，见文档 09 问题 4：改用独立 5V + 共地 + 470µF 电解电容） |
| 14 | 电机一转单片机就复位 | 电机从板载 5V 取电导致电压跌落 | 立刻**用独立 5V 供电给电机，并与板子共地**；临时应急：先不转电机，改用串口帧演示状态变化，等一下再补硬件 |

### 7.1 真正没法救时的降级方案（背下来）

1. **硬件全崩、只有串口能通** → 全流程用 `SIM T=` + `MODE MANUAL` + `LEVEL n` 演示 8 个状态，配合串口帧讲解，一样能把控制逻辑讲完整。
2. **串口也崩、只有板子能跑** → 用 K4 按到 20.0℃/60.0℃ 制造全速和停转，用拔传感器线制造 FAULT，靠肉眼和耳朵演示。
3. **板子也崩了** → 打开电脑上的源码，从 `config.h` 讲参数设计，从状态机讲控制逻辑，从串口协议讲接口设计。**代码和参数本身就是作品的一部分。**

| 命令 | 作用 | 备注 |
|---|---|---|
| `SIM T=45.0` | 注入模拟温度 45.0℃，进入仿真模式 | 支持小数和负数 |
| `SIM OFF` | 退出仿真，回到真实传感器 | 物理演示前必须发 |
| `MODE AUTO` | 切自动模式 | |
| `MODE MANUAL` | 切手动模式 | |
| `SET T=30.0` | 设目标温度（限幅 20.0~60.0℃） | 一键改 Tset，比按按键快 |
| `LEVEL 2` | 手动模式下直接指定档位 0~3 | 2 = 中速 66% |
| `STATUS` | 立即回一帧 | 调试时确认链路 |
| `RESET` | 恢复默认参数并清报警 | 回到演示起点 |

**上报帧格式**（每 1s 一帧，状态变化立即补发）：
`$S,<ms>,<T>,<SET>,<LEVEL>,<DUTY>,<ST>,<MODE>,<BUZ>,<SIM>,<SENSOR>`
示例：`$S,12345,355,350,2,66,MID,AUTO,0,0,OK`

`SENSOR` 字段取值：`OK` / `NOPRESENT` / `BADCRC` / `NOINIT`。
